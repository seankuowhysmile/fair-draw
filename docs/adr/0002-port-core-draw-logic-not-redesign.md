# 重寫時「移植」現有抽選／驗證邏輯而非重新設計，並沿用既有 15 項測試作為回歸基準

`core.js` 涵蓋人員與獎項驗證、密碼學安全的不放回抽樣、作廢與補抽、以及備份 JSON 的自我一致性驗證（`validateState`）。這部分是全系統對「正確性」要求最高、也最難靠肉眼審查發現遺漏邊界條件的地方——一旦在現場活動中抽錯人、漏排除已作廢者，是公開發生、無法悄悄修正的信任事故，且目前這套邏輯已有 15 項核心測試驗證過。

決定：重寫時把這部分當成「照著既有規則與測試集，翻譯成新語言（TypeScript）」，而不是重新設計演算法或規則本身；同一組測試案例原封不動搬到新測試框架（Vitest）繼續當驗收基準。UI、架構、打包流程、以及沒有被既有測試覆蓋的新功能，才是真正重新設計的範圍。

若未來有新的抽獎規則需求（例如加權機率、部門保障名額），屆時是在新語言裡重新設計該規則，不受本決策限制；本決策只限制「既有、已驗證、沒有新需求要改的規則」在這次重寫中維持邏輯不變。
